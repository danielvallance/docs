## Getting started

This pattern works with a Linux desktop environment and any browser-facing remote display stack.
The image is whatever your Dockerfile produces: XFCE, GNOME, or a bare window manager, running whichever applications your users need.
This guide uses one such combination: [noVNC](https://novnc.com/info.html), an open source Virtual Network Computing (VNC) client that runs in the browser, paired with a minimal Linux desktop and Firefox.

To run it, follow these steps:

1. Install the CLI.
   Use the [unikraft CLI](/docs/cli/unikraft) or the legacy [kraft CLI](https://unikraft.org/docs/cli/install).
   You need a [BuildKit](https://github.com/moby/buildkit) builder. The easiest way to get one is via [Docker](https://docs.docker.com/engine/install/).
   You can also set up and use BuildKit directly; see the [quick start](https://github.com/moby/buildkit#quick-start).

   :::note
   The unikraft CLI is the current standard, while kraft is the legacy version.
   Choose one of the CLIs below and only run the commands associated with it for the rest of this guide.
   :::

1. Clone the [`examples` repository](https://github.com/unikraft-cloud/examples) and `cd` into the `examples/novnc-browser/` directory:

   ```bash
   git clone https://github.com/unikraft-cloud/examples
   cd examples/novnc-browser/
   ```

Make sure to log into Unikraft Cloud and pick a [metro](/platform/metros) close to you.
This guide uses `fra` (Frankfurt, 🇩🇪):

<CodeTabs syncKey="cli">

```bash title="unikraft"
unikraft login
```

```bash title="kraft"
# Set Unikraft Cloud access token
export UKC_TOKEN=token
# Set metro to Frankfurt, DE
export UKC_METRO=fra
```

</CodeTabs>

The `UKC_TOKEN` and `UKC_METRO` environment variables are only supported by the legacy CLI.

:::caution
A noVNC desktop instance on Unikraft Cloud requires 4GB to run.
Request an increase in the instance memory quota when you need more memory.
:::

When done, invoke the following command to deploy this app on Unikraft Cloud.
The `--scale-to-zero` flag enables stateful [scale-to-zero](/features/scale-to-zero#stateful-scale-to-zero), so the desktop suspends with its memory intact when idle and restores when the user reconnects:

<CodeTabs syncKey="cli">

```bash title="unikraft"
unikraft build . --output <my-org>/novnc-browser:latest
unikraft run --metro fra \
  --name vnc-browser \
  -m 4G \
  -p 443:6080/tls+http \
  --scale-to-zero policy=on,cooldown-time=4000,stateful=true \
  --image <my-org>/novnc-browser:latest
```

```bash title="kraft"
kraft cloud deploy \
  --name vnc-browser \
  -M 4Gi \
  -p 443:6080/tls+http \
  --scale-to-zero on \
  --scale-to-zero-stateful \
  --scale-to-zero-cooldown 4s \
  .
```

</CodeTabs>

### Customize your deployment

The current deployment ships with Firefox, a tiling panel, and a small set of X11 utilities on top of Ubuntu.
Customizing the deployment means editing the `Dockerfile` to add the apps your users need, such as a different browser, an editor, or developer tools.
You can also adjust the screen geometry through the `WIDTH`, `HEIGHT`, and `DISPLAY_NUM` environment variables in `wrapper.sh`.

[Anthropic's Computer Use Demo](https://github.com/anthropics/claude-quickstarts/tree/main/computer-use-demo) inspired this example, which works well as a sandbox for computer-use automation that needs to drive a real desktop.

## Why this pattern works

Remote desktops power browser-based Linux GUIs, computer-use agents, secure browsing sessions, and disposable workstations.
These workloads are memory-hungry, security-sensitive, and interactive in bursts, and each of those pressures maps to a platform feature:

1. **Hardware isolation per session**:
   A desktop session runs untrusted browsers, untrusted documents, and arbitrary user input.
   Each desktop on Unikraft Cloud is its own microVM with its own kernel, and the minimal, single-purpose image keeps the attack surface small.

1. **Stateful suspend fits interactive sessions**:
   Users are active for minutes and away for hours.
   Stateful [scale-to-zero](/features/scale-to-zero#stateful-scale-to-zero) snapshots the whole microVM, open windows and running apps included, and restores it in under 10 ms when the user returns, so you pay for the seconds of actual use.

1. **Density that makes a desktop per user viable**:
   Desktop environments are memory-hungry, which normally rules out one VM per user.
   Unikraft Cloud packs up to 100K+ microVMs onto a single server, and suspended desktops consume no resources at all.

1. **Built for automation**:
   Computer-use agents drive a real desktop the same way a human does.
   Every desktop gets an ordinary HTTPS endpoint, so you can spin up a fresh, disposable environment per task and control it from a browser or a program.
