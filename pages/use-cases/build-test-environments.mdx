Give every build or test job its own microVM: your full toolchain, started from a snapshot in milliseconds, with that job's code injected at boot.

<ValueCards>
  <ValueCard title="Start chunky environments fast" metric="boots in < 10 ms" metricHref="/platform/instances#instance-templates">
    Pack the whole build environment—compilers, dependencies, warm caches—into a [template](/platform/instances#instance-templates): a snapshot with all that state already initialized.
    Size stops mattering.
  </ValueCard>
  <ValueCard title="Run as many as you need" metric="100K+ microVMs / server" metricHref="/features/scale-to-zero">
    The platform scales to fleets, not to a handful of runners: thousands of distinct templates, and idle environments cost nothing between runs.
  </ValueCard>
  <ValueCard title="Inject the code to build, instantly" metric="swap by image tag" metricHref="/features/roms">
    The code under test arrives as a [ROM](/features/roms)—a small data file attached at start.
    Same environment, different payload per job, no image rebuild.
  </ValueCard>
</ValueCards>

## Getting started

This pattern works with any toolchain.
The base image is whatever your Dockerfile produces: for example a JVM, a Node.js toolchain, or a Rust compiler.
Warm state such as fetched Gradle dependencies, installed `node_modules`, or a populated registry cache belongs to the [template](/platform/instances#instance-templates), captured once the environment has started up.
The [ROM](/features/roms) is a small data blob that contains files which are specific to a job.

This guide walks through the pattern with a Go toolchain, using the [`build-environments`](https://github.com/unikraft-cloud/examples/tree/main/build-environments) example.
The base image contains a Go server (`server.go`) that:

1. Writes to `/uk/libukp/template_instance` to turn the instance into a [template](/platform/instances#instance-templates).
2. Reads ROM source from `/rom/rom.go`.
3. Compiles it to `/run/rom.so` using `go build -buildmode=plugin`.
4. Loads the `Handler()` function from the plugin and serves its output over HTTP.

### Prerequisites

1. Install the CLI.
   Use the [unikraft CLI](/docs/cli/unikraft) or the legacy [kraft CLI](https://unikraft.org/docs/cli/install).
   You need a [BuildKit](https://github.com/moby/buildkit) builder.
   The easiest way to get one is via [Docker](https://docs.docker.com/engine/install/).
   You can also set up and use BuildKit directly; see the [quick start](https://github.com/moby/buildkit#quick-start).

   :::note
   The unikraft CLI is the current standard, while kraft is the legacy version.
   Choose one of the CLIs below and only run the commands associated with it for the rest of this guide.
   :::

1. Clone the examples repository and enter the example directory:

   ```bash
   git clone https://github.com/unikraft-cloud/examples
   cd examples/build-environments/
   ```

Make sure to log into Unikraft Cloud and pick a [metro](/platform/metros) close to you.
This guide uses `fra` (Frankfurt, 🇩🇪):

<CodeTabs syncKey="cli">

```bash title="unikraft"
unikraft login
```

```bash title="kraft"
# Set Unikraft Cloud access token
export UKC_TOKEN=token
export UKC_METRO=fra
```

</CodeTabs>

### Step 1: Package and push the base runtime image

Package and push the base Go runtime image (see `server.go` for the runtime implementation):

<CodeTabs syncKey="cli">

```bash title="unikraft"
unikraft build . --output <my-org>/go-build-env:latest
```

```bash title="kraft"
kraft pkg \
  --name index.unikraft.io/<my-org>/go-build-env:latest \
  --plat kraftcloud \
  --arch x86_64 \
  --rootfs-type erofs \
  --push \
  .
```

</CodeTabs>

The server in `server.go` loads `/rom/rom.go`, compiles it to `/run/rom.so` using `go build -buildmode=plugin`, and invokes `Handler()` from the plugin.

### Step 2: Create a template from the base image

Create a short-lived instance from the base image (without ROM attached).
The server writes to `/uk/libukp/template_instance` and turns the instance into a [template](/platform/instances#instance-templates) before serving requests:

<CodeTabs syncKey="cli">

```bash title="unikraft"
unikraft run --metro fra \
  --name go-build-env \
  -m 512M \
  --image <my-org>/go-build-env:latest
```

```bash title="kraft"
kraft cloud instance create \
  --start \
  --name go-build-env \
  -M 512Mi \
  <my-org>/go-build-env:latest
```

</CodeTabs>

### Step 3: Package ROM payloads

A [ROM](/features/roms) can carry any files a job needs: sources, test suites, or configuration.
In this example, each ROM contains a Go function implementation.

<CodeTabs syncKey="cli">

```bash title="unikraft"
unikraft build rom1/ --output <my-org>/go-rom1:latest
unikraft build rom2/ --output <my-org>/go-rom2:latest
```

```bash title="kraft"
kraft pkg \
  --plat kraftcloud \
  --arch x86_64 \
  --name index.unikraft.io/<my-org>/go-rom1:latest \
  --rom-type erofs \
  --push \
  rom1/
kraft pkg \
  --plat kraftcloud \
  --arch x86_64 \
  --name index.unikraft.io/<my-org>/go-rom2:latest \
  --rom-type erofs \
  --push \
  rom2/
```

</CodeTabs>

### Step 4: Launch test environments from template

Create an instance with the first ROM.
The `--scale-to-zero` flag enables [scale-to-zero](/features/scale-to-zero), so the environment releases its resources when idle and wakes on the next request:

<CodeTabs syncKey="cli">

```bash title="unikraft"
unikraft run --metro fra \
  --name go-build-env-rom1 \
  -p 443:8080/tls+http \
  --scale-to-zero policy=on,cooldown-time=1000,stateful=true \
  --rom image=<my-org>/go-rom1:latest,at=/rom \
  --template go-build-env
```

```bash title="API"
curl -X POST "https://api.fra.unikraft.cloud/v1/instances" \
  -H "Accept: application/json" \
  -H "Authorization: Bearer ${UKC_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "go-build-env-rom1",
    "template": {
      "name": "go-build-env"
    },
    "autostart": true,
    "service_group": {
      "services": [
        {
          "port": 443,
          "destination_port": 8080,
          "handlers": ["tls", "http"]
        }
      ]
    },
    "scale_to_zero": {
      "policy": "on",
      "stateful": true,
      "cooldown_time_ms": 1000
    },
    "roms": [
      {
        "name": "go_function",
        "image": "index.unikraft.io/<my-org>/go-rom1:latest",
        "at": "/rom"
      }
    ]
  }'
```

</CodeTabs>

The instance will compile the ROM into a plugin on first start, which may take a few seconds.

```bash title="kraft"

```

</CodeTabs>

## Why this pattern works

This build/test environment uses three reusable layers:

1. **Base runtime image**:
   Your toolchain plus a small control server (Go in this example).
   Build once, reuse many times.

1. **[ROM](/features/roms) payload**:
   A source-only image (here, `rom.go`).
   Update per job.

1. **[Template](/platform/instances#instance-templates) snapshot**:
   A pre-initialized runtime used to speed up new instance startup.
